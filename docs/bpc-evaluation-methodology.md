# BPC Evaluation Methodology

## 1. Purpose

This note records the problems found in the first BPC experiment and defines how later parameter tuning and algorithm comparison shall be evaluated.

The objective is to compare the fixed-threshold baseline and adaptive directional BPC without treating synthetic labels as ground truth for unknown physical sensor defects.

## 2. Problems Found

### 2.1 The source RAW is not known to be defect-free

The MIT-Adobe FiveK input is a Bayer RAW image captured by a real camera. It may already contain physical sensor defects, corrected pixels, or locally unusual values. A single DNG does not provide enough evidence to determine which case applies.

The file currently named `clean_rggb.pgm` therefore means only "before synthetic injection." In evaluation terminology it shall be called the reference RAW, not a proven defect-free RAW.

### 2.2 Synthetic labels do not cover physical sensor defects

`defects.csv` records only the locations changed by the defect injector. A detection outside those locations is not proven to be a false physical-defect detection.

Such a detection shall be called an off-target detection or off-target correction relative to the synthetic restoration task.

### 2.3 Single-frame data cannot identify stuck pixels

A physical stuck pixel is defined by persistent behavior at one sensor coordinate across multiple RAW frames. One frame cannot establish that persistence. A fixed value that is high or low relative to its local same-CFA neighborhood is observable only as a spatial high or low outlier; a locally plausible fixed value is indistinguishable from valid image content.

Synthetic stuck corruption is therefore excluded from all new single-frame BPC training, validation, and test datasets. It shall not contribute to tuning objectives, diagnostic metrics, or performance claims. Historical version 0.1 injector results retain their stuck rows for reproducibility but are not conforming tuning datasets under this methodology.

Reliable stuck-pixel identification requires multiple RAW frames from the same physical sensor, aligned by sensor coordinate under changing scene or illumination conditions. This decision is recorded in [ADR 0001](adr/0001-exclude-stuck-from-single-frame-bpc.md).

### 2.4 Detection-only metrics are incomplete

Coordinate TP, FP, recall, precision, and F1 measure whether a location was flagged. They do not measure whether the replacement value moved the corrupted pixel closer to its reference value or whether the algorithm damaged other pixels.

F1 therefore remains a secondary diagnostic metric, not the primary tuning objective.

### 2.5 The first sweep reused its evaluation image

The initial parameter search selected and reported a configuration on the same image and injection instance. Those measurements are exploratory results and may contain selection bias. They are not final evidence of generalization.

### 2.6 FiveK cannot provide real-defect ground truth

FiveK contains natural RAW scenes from many cameras, but it does not provide the repeated dark frames, flat-field frames, or fixed sensor-coordinate sequences needed to confirm physical bad pixels.

More FiveK images improve scene diversity for synthetic restoration. They do not convert the experiment into validation on real sensor defects.

## 3. Evaluation Scope

The evaluation is divided into two layers.

### 3.1 Guaranteed synthetic inputs

Procedural flat fields, gradients, edges, and textures are generated directly as Bayer RAW12. A more natural synthetic scene may be rendered as linear RGB and mosaiced into RGGB.

These inputs are guaranteed not to contain physical sensor defects because every sample is generated by software.

### 3.2 Natural paired inputs

For each compatible FiveK DNG:

```text
R   = reference RAW before injection
C   = corrupted RAW produced from R
O_R = BPC output produced from R
O_C = BPC output produced from C
```

This layer evaluates whether BPC reverses the known synthetic corruption while preserving every location that the injector did not change.

It does not claim that `R` is physically defect-free.

## 4. Pre-Injection Detector Run

For every candidate configuration, the detector shall run on both `R` and `C` without overwriting either input.

```text
B_R = detections on R
B_C = detections on C
I   = injected locations
```

The sets are interpreted as follows:

```text
B_R                       : detector response already present on the reference
(B_C - B_R) intersect I   : new target detection after injection
(B_C - B_R) outside I     : new off-target detection after injection
B_R intersect I           : injected position already detected before injection
```

`B_R intersect I` shall be reported separately. It is not evidence that the injection caused the detection.

The pre-injection run characterizes detector behavior. It does not determine whether a reference detection is a real sensor defect.

## 5. Primary Restoration Metric

Define:

```text
D_hot  = injected hot pixel locations
D_dead = injected dead pixel locations
D      = D_hot union D_dead
U      = all valid locations not changed by the injector
```

Conforming datasets contain no synthetic stuck rows.

For each defect type `q` in `{hot, dead}`:

```text
E_initial_q  = sum(abs(C[i] - R[i]))   for i in D_q
E_residual_q = sum(abs(O_C[i] - R[i])) for i in D_q
RG_q         = 1 - (E_residual_q / E_initial_q)
```

The balanced restoration gain is:

```text
BRG = (RG_hot + RG_dead) / 2
```

Interpretation:

```text
RG_q = 1 : complete restoration for defect type q
RG_q = 0 : no improvement over leaving type q unchanged
RG_q < 0 : correction increases the error for type q
```

An injection instance with `E_initial_hot = 0` or `E_initial_dead = 0` is invalid and shall be regenerated.

`RG_hot`, `RG_dead`, and `BRG` are calculated per image. Training search aggregates each candidate configuration by image identity and uses mean training `BRG`. Hot and dead receive equal weight even when their injected counts or corruption magnitudes differ. Final configuration selection uses mean validation `BRG`.

Collateral error is deliberately excluded from the `BRG` numerator. Increasing the injected-defect count must not make off-target correction appear cheaper. Background and injection-induced corrections are controlled independently by Section 6.

## 6. Safety Constraints

Let `V` be every valid evaluated pixel after the border exclusion. The background correction rate is:

```text
BCR = count(O_R[i] != R[i] for i in V) / count(V)
```

`BCR` measures how aggressively a configuration modifies the pre-injection reference. It does not label those corrections as false physical-defect detections.

The injection-induced off-target correction rate is:

```text
IOTCR = count(O_C[i] != O_R[i] for i in U) / count(U)
```

`IOTCR` isolates output changes outside the injected locations that appear only after synthetic corruption is introduced.

Parameter tuning shall not hide `BCR` or `IOTCR` inside a weighted restoration
score. First select the highest-mean-BRG adaptive operating point on tuning data.
Its mean BCR and IOTCR define the matched comparison budget. Train the baseline
under those same numerical limits so that it cannot obtain BRG by correcting
more background or inducing more off-target changes than the selected adaptive.

The selection rule is:

```text
select the adaptive candidate with highest mean BRG
freeze that candidate's mean BCR and mean IOTCR as the comparison budget
reject baseline thresholds whose mean BCR or mean IOTCR exceeds that budget
select the eligible baseline threshold with highest mean BRG
if BRG is tied, prefer lower mean IOTCR, then lower mean BCR
```

The budget and both final operating points are learned only from tuning data.
Held-out test data reports whether each frozen operating point remains within
the tuning budget; test data must not redefine the budget or selection.

## 7. Required Diagnostic Results

Every baseline-versus-adaptive comparison shall additionally report:

- `RG_hot`, `RG_dead`, and `BRG`;
- coordinate recall, precision, and F1 as secondary metrics;
- replacement MAE at injected locations;
- `BCR`, `IOTCR`, and off-target MAE;
- results by R, Gr, Gb, and B phase;
- results by flat, edge, and texture region;
- results by local signal level and injected severity;
- results for locally observable and locally indistinguishable defects.

## 8. Dataset Split and Tuning

### 8.1 Dataset split

Compatible images shall be split by image identity after filtering:

```text
70 percent : training parameter search
10 percent : validation and final configuration selection
20 percent : held-out test
```

Images, crops, or injection instances derived from one source image must remain in the same split.

Injection shall use a deterministic seed derived from the image identity rather than seed `0` for every image. The seed and injector parameters must be recorded so that every result is reproducible.

The workflow is:

```text
search configurations on training data
select one configuration on validation data
freeze the configuration
run the held-out test once
```

The test result shall not be used for further parameter adjustment.

### 8.2 Parameter search schedule

The adaptive configuration contains five parameters:

```text
T0_R, T0_G, T0_B, k_s, k_a
```

The search uses three refinement stages followed by one final shift audit.

#### Stage 1: shared-threshold coarse search

```text
T0_R = T0_G = T0_B
T0 in {0, 256, 512, ..., 3840, 4095} : 17 values
k_s in [0, 12]                        : 13 values
k_a in [0, 12]                        : 13 values

17 * 13 * 13 = 2,873 candidates
```

#### Stage 2: per-CFA threshold separation

Retain the three best distinct Stage-1 threshold regions. For each region:

```text
T0_R, T0_G, T0_B = region center +/- 256, step 64 : 9 values each
k_s, k_a         = associated best value +/- 2    : at most 5 values each

3 * 9^3 * 5^2 = 54,675 candidates
```

#### Stage 3: local refinement

Refine around the best Stage-2 configuration:

```text
T0_R, T0_G, T0_B = best value +/- 64, step 16 : 9 values each
k_s, k_a         = best value +/- 2            : at most 5 values each

9^3 * 5^2 = 18,225 candidates
```

#### Final shift audit

Freeze the three refined thresholds and recheck the complete shift range:

```text
k_s in [0, 12]
k_a in [0, 12]

13 * 13 = 169 candidates
```

The maximum scheduled count before clipping, boundary deduplication, or cross-stage deduplication is:

```text
2,873 + 54,675 + 18,225 + 169 = 75,942 candidates
```

Values outside the legal ranges `T0_CFA in [0, 4095]` and `k_s, k_a in [0, 12]` shall be clipped and duplicate configurations shall be evaluated once.

### 8.3 Separable evaluation

For fixed `k_s` and `k_a`, changing one `T0_CFA` affects only output centers belonging to that CFA phase. This is valid because the evaluator reads an immutable input and directional prediction and activity do not depend on earlier corrections.

For `adaptive_v2`, define the per-center cutoff:

```text
C = clamp(abs(X - P) - (P >> k_s) - (G_min >> k_a), 0, 4096)
```

For integer `T0_CFA` in `[0, 4095]`, the center is detected exactly when
`T0_CFA < C`. The metric bank must use this cutoff; the historical v1 cutoff
based on distance outside `[N_min, N_max]` and `R_N` is not compatible with v2.

The evaluator may therefore measure each per-CFA threshold contribution independently and combine the scalar metric contributions offline. Under the planned schedule, the expensive evaluation count is bounded by:

```text
Stage 1           : 2,873
Stage 2           : 3 * 5^2 * (3 * 9) = 2,025
Stage 3           :     5^2 * (3 * 9) =   675
Final shift audit : 13^2             =   169
Total                                  5,742 evaluator passes
```

All candidate metrics shall still be reconstructed and ranked as the full five-parameter configurations. This optimization changes evaluation cost, not the candidate set or selection rule.

### 8.4 AMD Vitis Vision vendor baseline

The parameter-free AMD Vitis Vision `xf::cv::badpixelcorrection` function is a
third comparison point, separate from the tuned fixed-threshold baseline. For a
center sample `X`, let `N` contain the eight same-CFA neighbors at row and column
offsets in `{-2, 0, 2}`, excluding the center. Its interior-pixel behavior is:

```text
N_min = min(N)
N_max = max(N)
O     = clamp(X, N_min, N_max)
```

The host reference uses constant-zero samples outside the frame to match the
AMD API's default `XF_BORDER_CONSTANT` mode. Evaluation still excludes the
outer two rows and columns under the common metric contract, so border behavior
does not affect `RG_hot`, `RG_dead`, `BRG`, `BCR`, or `IOTCR`.

AMD BPC has no algorithm parameter to train. It shall be evaluated as published
on the already frozen held-out split, using the recorded per-image injection
seeds. The existing fixed-threshold and adaptive-v2 per-image results remain
immutable comparison inputs. AMD BPC is not rejected or retuned if it exceeds
the adaptive tuning BCR/IOTCR budget; that excess is part of the reported
result. A new algorithm variant derived from test results requires a fresh
split and is not covered by this vendor-baseline comparison.

### 8.5 OpenISP gradient DPC baseline

The OpenISP comparison point reproduces the `gradient` mode in
`cruxopen/openISP` commit
`d4947e1aa5f4af83c3640131dbca8a675b613ec6`. For center `X` and the eight
same-CFA neighbors `N` at two-pixel row and column offsets, detection is:

```text
detected = all(abs(X - n) > T for n in N)
```

On detection, OpenISP computes vertical, horizontal, left-diagonal, and
right-diagonal gradients as the absolute difference between `2*X` and each
directional neighbor-pair sum. It selects the minimum with that tie priority
and replaces `X` with the selected pair's rounded-up integer mean. Otherwise it
passes `X` through. The source uses reflected two-pixel padding; the common
metric contract still excludes the outer two rows and columns.

The published configuration uses `T=30`, `gradient` mode, and clip `1023` for
its 10-bit pipeline. This repository fixes `T=120` for RAW12, scaling the
published threshold by four while retaining the same normalized signal
difference. Output is naturally within RAW12, so clipping uses `[0,4095]`.
This bit-depth mapping is a declared comparison choice, not a trained result.

OpenISP originally places DPC before BLC. The comparison reference applies the
same DPC behavior to the post-BLC `R` and `C` frames used by every existing BPC
metric, so `RG_hot`, `RG_dead`, `BRG`, `BCR`, and `IOTCR` remain directly
comparable. It reuses the frozen adaptive-v2 held-out split and injection seeds;
the OpenISP threshold must not be adjusted from held-out results. As with AMD,
budget excess is reported rather than used to reject or retune the algorithm.

## 9. Claim Boundary

Evidence from this methodology may support the following claim:

> Adaptive BPC improves recovery of synthetic isolated hot and dead corruption over the fixed-threshold baseline at the same off-target correction budget on held-out Bayer scenes.

It does not support the following claim:

> Adaptive BPC has been proven to detect and correct all physical sensor defects.

Validation of the second claim requires RAW calibration data from the same sensor unit, including repeated dark and flat-field captures with upstream BPC disabled.

It also does not support a claim that the algorithm identifies temporal stuck pixels. A physical stuck pixel corrected because it appears as a high or low spatial outlier remains an unclassified detection.

## 11. One-image Pipeline Experiment

The daily smoke/sweep experiment runs the Section 8 candidate schedule on one
image. It does not create train/validation/test splits or establish generalization.
R and C in every metric are post-BLC frames. CSV coordinates refer to the same
crop; pre-BLC CSV pixel values must not be used as post-BLC metric targets.

For this exploratory run the historical shared baseline threshold 1063 is an
explicit recorded operating point, not a newly calibrated optimum. Its measured
BCR/IOTCR on the same image supply the two budgets. Retain up to three eligible
Stage-1 entries with distinct shared T0 values; preserve each entry's k_s/k_a.
If none is eligible, report no eligible adaptive configuration and stop refinement.
This does not authorize silently relaxing the budgets.

The sweep may precompute integer metric sums independently for R/Gr/Gb/B.
For fixed shifts, each center changes from predicted value to original value at
one integer T0 boundary. Prefix sums over these boundaries produce the same
per-phase metrics for every T0. Combine Gr and Gb using the same T0_G, then
compute ratios from the summed numerators and image-wide denominators.
The original BPC functions remain the oracle: compare optimized metrics with
paired full-frame calls at directed configurations and at the selected result.

Full sweep outputs include candidate configuration, stage, BRG, RG_hot, RG_dead,
BCR, IOTCR, eligibility, selected configuration, baseline and timing. Diagnostic
region/severity bins from Section 7 remain outside this one-image smoke result.
